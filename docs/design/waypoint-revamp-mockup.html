Reversed from v1. Making an agent own a workstream put its instructions in two places — the agent's own agent.md and the workstream's “standing brief” — with no rule for which wins, and gave one agent three simultaneous relationships. Views
A view is a saved filter. One concept — a project view is just a view whose filter includes that project.
A view is also how an agent gets a scope. An agent is one brief (agent.md, always one place) plus the views it watches. “Watch everything matching label:security” is a brief with a scope, expressed in a primitive that already exists. Assigning an agent to a single ticket is just a scope of one — same model, no special case.
