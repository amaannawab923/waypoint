Where this can't reach Phoenix's bar — said plainly, not papered over

From provider-ux-v2.md §6, plus what surfaced only while building this. Not fixed by a better layout — each has its own real prerequisite.

1
29 rows say nothing, on purpose — and that's not a Phoenix-reachable table. Phoenix never ships a described-provider row with an empty status; every one of its 17 is one they wrote themselves. Expand "Show 29 more" below and every column past the name is an em dash. The fix is upstream plugin work (declaring auth/models for more of the 35), not a layout this screen can invent its way around.
2
First run is "Not installed" almost everywhere. Toggle the state selector above to "Not installed" — that's the honest default for nearly every provider on a fresh machine, and install flows are explicitly out of scope for this pass. This screen can only describe that state truthfully, not remove it.
3
Sign in now opens a real terminal, and it looks like one. The superseded mockup faked a branded OAuth popup to hide the CLI underneath. That requirement is gone, so Claude Code's and Codex's sign-in shows the actual command about to run in a real terminal panel — rougher than Phoenix's equivalent, because Phoenix has no CLI to reveal at all. This is a deliberate return to honesty, not an oversight; see provider-ux-v2.md §4.3.
4
The Copilot's model list can't match Phoenix's cross-vendor default. Switch to the Copilot tab — the picker is two Anthropic models, full stop, because the Copilot calls the Claude Agent SDK directly and nothing else. Phoenix's assistant can default to any configured vendor. That's a real capability gap this screen is not hiding behind a bigger-looking dropdown.
5
Every model id and count on this page is transcribed from the real plugin manifests (packages/plugins/src/agents/impl/*/index.ts, read-only), not the shipped app's invented ones — Amp's four options are effort tiers (low/medium/high/ultra), not vendor model names, and Mistral's are mistral-medium-3.5 / devstral-small / local. The shipped page currently shows neither correctly; confirm this list against the manifests again before it ships, since both sides can drift.
